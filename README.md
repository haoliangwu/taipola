# taipola

一个极简但强大的 Markdown 编辑器：**光标所在的语法块显示 Markdown 源码，光标一离开就渲染成最终的样子**。没有左右分栏，没有预览按钮。

```bash
pnpm install
pnpm dev      # http://localhost:5178
pnpm build    # 产出 dist/
pnpm test     # vitest browser mode（真实 Chromium）
```

## 测试

测试跑在 **vitest browser mode**（Playwright + 真实 Chromium），不是 jsdom：编辑器输入走浏览器原生管线（`keydown → beforeinput → DOM 变更 → input`），点击/键盘由 userEvent 与真实坐标驱动，因此 jsdom 无法模拟的 `beforeinput`、原生选区、拖选、IME 行为都能真实覆盖。

```bash
pnpm test          # 跑一遍
pnpm test:watch    # 监听
```

首次运行会下载 Chromium 到本项目 `.pw-browsers/`（沙箱环境装不进 `~/Library/Caches/ms-playwright` 时用 `PLAYWRIGHT_BROWSERS_PATH=$PWD/.pw-browsers`）。

`src/test/editorTestUtils.tsx` 提供真实操作助手：

- `clickInRun` / `clickAtLine`：按真实坐标点击 run / 空行，浏览器自行解析字形位置（坐标是相对目标元素的；传绝对坐标会把光标点偏到行末）
- `typeText` / `pressBackspace` / `pressEnter` / `pressShiftEnter`：真实键序列
- `caretFromDom`：DOM 选区 → 文档源码偏移（含空行锚定）
- `assertDomMatchesSource`：DOM 各行拼接后必须与文档源码逐字一致（`\n+` 尾部除外）

覆盖的回归场景（`src/components/Editor.test.tsx`、`src/App.test.tsx`）：

1. **标题按 Enter**：光标中间拆分、行末新增空行（行末不再是 no-op）、Shift+Enter 软换行
2. **列表**：末项 Enter 续行、空 bullet 再次 Enter 退出列表且**保留空行**、退出后光标停在空行上
3. **空行**：点击空行、空行上打字不丢字
4. **鼠标选中**：选区跨越 reveal 翻转（块级标记显现/折叠）时视图重渲染不摧毁选区
5. **撤销 / 数据完整性**：backspace 删除后源码持久化、backspace 后继续输入
6. **NotFoundError 回归**：各位置反复 Enter、文档底部（块外）点击后 Enter + 打字，均不抛 React 异常且 DOM 与模型一致
7. **草稿持久化**：编辑后立刻 `pagehide`（刷新前）草稿不回退

## 现在能做什么

- 即时渲染：段落、标题、列表、引用、代码块（highlight.js 高亮）、表格、任务列表、脚注
- 光标进入块时，块级标记就地显现（标题 `#`、列表 bullet、引用 `>`、代码围栏 ```、任务框），光标离开即折叠成渲染态
- 行内标记同理：光标落在构造内时 `**`、`*`、`~~`、反引号、`[链接](url)` 显示为源码
- 中文输入法原生可用（拼音候选、联想词不受干扰）
- 撤销：`Cmd/Ctrl + Z` / `Cmd/Ctrl + Shift + Z` 走自带的快照栈，恢复时连光标一起还原
- 打开 / 保存 md 文件；浏览器支持时写回**原文件**（File System Access API），否则降级为下载
- 侧边大纲：随光标高亮所在章节，点击跳转
- 自动保存草稿到 localStorage，关页面不丢内容
- 导出 HTML / 导出 MD
- 主题：默认跟随系统，右上角可切换 **浅色 → 深色 → 跟随系统**（选择会被记住）

快捷键：`Cmd/Ctrl + B/I/K/E`（粗体/斜体/链接/行内代码）、`Cmd/Ctrl + 1..6`（标题级别，重复按同级别可取消）、`Cmd/Ctrl + Shift + K`（删除整行）、`Cmd/Ctrl + O/S`（打开/保存）、`Cmd/Ctrl + Shift + S`（另存为）、`Cmd/Ctrl + Shift + \`（切换大纲）。

### 主题

`:root` 携带浅色配色（默认，纯白底）。深色有两条触发路径，都写在 `src/styles.css`：

- **系统偏好**：`@media (prefers-color-scheme: dark) :root:not([data-theme='light'])`
- **显式选择**：`:root[data-theme='dark']`，写在最后，因此总是优先于系统偏好

`useTheme()`（`src/lib/theme.ts`）负责把选择写到 `<html data-theme>` 并存进 localStorage。`system` 时移除该属性，交还给媒体查询。

配色全部走 CSS 变量，所以**切换主题不影响行高与布局**。代码高亮的 token 颜色在深色下单独重新着色——highlight.js 只提供浅色主题，深色下若不覆盖会对比度不足。

## 架构：源码模型 + 映射视图

文档模型是纯 Markdown **源码**；屏幕上显示的是它的一个*视图*，其中语法标记作为 DOM 文本存在，但构造闭合且光标离开后折叠为**零宽**（`display: none`）。`**加粗**` 占 6 个源码字符、只占 2 个排版字符。

```
.doc                          唯一的滚动容器（contenteditable）
└── .blk[data-block]          一个 markdown-it 块，data-src-start 记录块起点
    └── [data-vline]          块内的一行源码 = 一个行盒，data-src 记录行起点
        └── [data-run]        一个样式/可见性一致的 run，data-src 记录块内源偏移
```

**光标就是一个源码偏移**。屏幕位置由视图推导；落在折叠标记内的光标画在最近的可见字符上，绝不会消失进零宽盒。每个可见字符都记得它来自哪个源码偏移，每个源码偏移都能从视图到达——标记也在其中——所以光标不可能落进缝隙。

三件事同时成立的原因：**标记始终留在 DOM 里**（只是零宽）。浏览器看到的是完整、稳定的字符序列（换行、列对齐、方向键移动都原生工作），隐藏构造不占宽度，光标始终可以在源码和屏幕之间互映射。

### 行内与块级标记的显现规则

- **行内构造**（`**`、`*`、`~~`、`` ` ``、`[]()`）：光标落在构造内部时，它的开/闭标记显示为普通文本，可原地编辑；其它闭合构造折叠。
- **块级标记**（标题 `#`、列表 bullet、任务框、引用 `>`、代码围栏）：光标在块内任意位置时，该块的所有行级前缀显现（渲染为暗色 `rn-dim`）；光标离开块即全部折叠。这与 Typora 的"每个语法块独立在预览/编辑模式间切换"一致。
- **代码围栏**：围栏行在光标进入代码块时显现（含语言标识），代码内容行永远是字面文本——其中的 `**` 不会被当成加粗。
- **表格**：单元格是网格项（`cellRuns`），管道符不参与布局；单元格内的行内标记显现时仍在自己的列内，不会撑出额外列。

### 为什么不是"透明 textarea 叠在渲染层上"

第一版就是这么做的，那是**结构性缺陷**，不是精度问题：

`textarea` 的高度恒等于 `行数 × 行高`，而渲染层的高度由内容决定。两者天生不等（实测一份 59 行的文档差 **350px**）。只要不等，"同步滚动"在任何意义上都无法精确——差值会**逐块累加**，越往下偏得越狠。

我在这条路上修过三轮（锚定最上方块、归一化滚动范围、增量 padding 恢复），把误差压到了 0.3px，但那是**在两个不可调和的东西之间做映射**。根本矛盾是：

> "源码行数决定高度" 与 "每块渲染成多行样式化内容" 无法同时成立。

实测数据很直接：一个渲染块**必然**比它的源码行占更多行。要让两层等高，只能把内容缩放到 **0.33**——15 个块里 14 个需要缩放，9 个严重变形。**此路不通。**

现代编辑器（Typora、Obsidian Live Preview）的做法都是**不要两个容器**。taipola 现在也是：一个容器，光标就在渲染出来的文字里，每个 run 都带源码偏移。

### 关键约定与不变量

- `ViewRun.src` / `data-src` 一律是**块内偏移**；`.blk` 的 `data-src-start` 是文档偏移。换算只在点击处理器里做一次。
- **run 分段在隐藏/显现两个状态间保持一致**（token 边界 + 块级标记边界预先定死），显现只切换 CSS 类、从不替换文本节点——否则锚在相邻文本里的光标会被挪走。
- **块视图按官方行跨度补足空行**：解析器会把块尾的空白行从 raw 里剥掉（markdown-it 的列表范围常覆盖末项后的空行），视图必须按 `endLine - startLine` 补齐空行盒，空行上的光标才有落点。
- **源代码永远是权威；DOM 只是反射。** 光标状态是源码偏移，DOM 选区读回只在真实手势之后才被信任（`placedByUs` 守卫）。
- `userEditPending`：`beforeinput` 置位、`input` 消费，只有真实用户编辑才从 DOM 重建源码；重渲染引起的 DOM 变动不会反向写回（否则折叠标记会被删掉）。
- **Enter 永远被接管**（光标在块外时也不例外）：原生 contenteditable Enter 会向 DOM 注入 `<br>`/`<div>`，下一次重渲染就抛 `NotFoundError: removeChild`。`onInput` 里还会清掉已混入的孤儿元素。
- `assertSourcePreserved`（dev）：每个块都必须恰好覆盖源码对应区间，一字不丢。改块收集逻辑时保持它安静。

### 会破坏光标的坑（都踩过）

1. **`focus()` 会重置选区。** 必须先 `focus()` 再 `setRange()`。反过来写会静默丢弃刚设好的光标，之后每次击键都插到行首——表现为输入**逆序**（打 `ABC` 得到 `CBA`）。且要 focus 的是**可编辑根**（`.doc`），不是内部块 div——块不可聚焦，键盘输入会落空。
2. **React 重渲染会重置 `contenteditable` 内的选区。** 模型更新后浏览器把选区扔回偏移 0。所以每次输入后都把光标位置存进 `pending`，在 layout effect 里重新应用。
3. **点击必须显式定位光标。** 块已是可编辑态时若只 `preventDefault()` 而不自己算位置，光标会停在原处。定位用 hit-test 找到 run，再按 `data-src` + 测量换算成源码偏移。
4. **块级标记不能"光标到行就显示"。</br>** 早期实现只在光标位于标记本身时显示前缀——结果为列表/标题/引用永远没有编辑态。现在的规则是**块级**：光标在块内 => 该块所有行的前缀显现；离开即折叠。配合上面第 4 条（分段一致），显现过程不移动光标。
5. **`revealFrom` 必须是行内偏移。** 曾经把块内偏移直接拿去和行内 token 偏移比较，多行块（列表、代码块）里除了第一行，行内标记永远不显现。
6. **表格单元格的 `data-src` 不能二次加偏移。** 单元格 run 已经带块内偏移，再叠加 `pieceStart + lead` 会让第二个单元格起的映射全部错位。

### 撤销

`contenteditable` 的原生撤销栈跨块不可靠（块会挂载/卸载），所以用**自己的快照栈**：每次结构性修改前压入 `{value, caret}`，`Cmd/Ctrl+Z` / `Cmd/Ctrl+Shift+Z` 在栈间移动，恢复时连光标一起还原。注意去重只与"上一次真正压入的快照"比较——不能用占位初值去重，否则第一次编辑永远无法撤销。

## 已知限制

- **表格各列等宽**（`grid-auto-columns: minmax(0, 1fr)`），不做按内容自适应；无边框与表头样式。
- **空行按源码行数渲染**：空源行与折叠的围栏行各占一个空行盒；连续空行不再合并成一个盒子。
- **标题前缀按块显现**：光标在标题行时 `# ` 显示为暗色；不在该块时折叠。
- 图片会按行内元素渲染，高度受限于一个行盒；加载完成后不会引起位移。
- mermaid、数学公式尚未支持。
- 单文档全量重解析，超大文件（数万行）会有输入延迟。
