# ADR-0001: 编辑器内核暂不原生化（评估结论留存）

- 状态：已评估，暂不执行（2025-XX 决定）
- 关联：换行类 bug（标题回车光标错位、段落二次回车失效、Backspace 偶发 NotFoundError、列表同类问题）

## 背景：问题机制链

报告的四类换行问题不是四个独立缺陷，而是同一个设计冲突的四个表现：

```
浏览器（用户输入时是 DOM 的唯一主人）
    vs
React（重渲染时也写 DOM，再把光标"重放"回原处）
```

当前编辑管线为：keydown 里做模型编辑 → React 重渲染 → layout effect 用 `pending` 把光标重放回 DOM。两次权威交替之间任何时序错位（React 批处理、浏览器 clamp 光标、焦点顺序）都会造成 **DOM 光标与模型光标漂移**：

- 漂移后下一次 Enter 从错误位置读取 `liveCaret`，把 `\n` 插错位置或插到文档末尾（"回车没反应"、"光标跑到下一行开头"）。
- Backspace 时浏览器按自己的语义改 DOM，React 重渲染又要卸载"它以为还在"的节点 → `removeChild` NotFoundError。

为此堆叠的补丁（`userEditPending`、`sanitizeDom`、`stripForeignText`、DOM 分叉检测 + 强制重挂载、`resetKey`）本质上都是同一个冲突的创可贴。

## 评估结论

**方案 A（Editor 内核原生化：React 只做外壳）**：

| 问题类 | 方案 A 的效果 |
| --- | --- |
| removeChild NotFoundError | 结构性消灭（没有 React 协调器就没有 React 卸载不存在节点），上述补丁全可删除 |
| 光标漂移引发的换行错乱 | 大部分消灭（原生内核在构建 DOM 后的同一同步帧内重放光标，漂移窗口归零） |
| 映射算法问题（行末语义、空行归属） | 框架无关，不会自动消失，但成为同步纯逻辑，好修好测 |

成本与可行性：
- `lib/` 层（markdown 解析、view 映射、撤销栈、editCommands）全部保留，本就不依赖 React。
- DOM 契约（`data-block`/`data-vline`/`data-run`）不变，现有 21 个测试继续有效，可作重构安全网。
- 主要重写：命令式 DOM 构建/更新、原生事件绑定、原生选区同步；React 组件退化为薄壳。
- IME 路径已有原生 `beforeinput` 经验，风险可控。

**结论**：方案 A 值得做且条件成熟，但当前决定是暂不执行——在现有架构上逐 bug 修补成本更低，代价是这一整类问题可能复发。

## 触发条件（满足任一即重新评估）

- 换行/光标类 bug 再次成批出现，或需要新的交互式补丁来维持现状；
- 需要新增与编辑区 DOM 强交互的特性（复制/粘贴富文本、拖放、跨块重排）时遇到结构性阻力；
- 基于 React 的渲染层开始明显拖慢编辑响应（当前未观察到）。

## 执行预案（若重新评估通过）

1. 先在当前代码上把已知 bug 复现成失败测试（重构的验收标准）。
2. 迁移 Editor 内核：`src/editor/` 原生模块（DOM 构建、事件、选区），`Editor.tsx` 退化为薄壳。
3. 验收：21 + 新增回归测试全绿 + 浏览器实测。
