# ADR-0001: 编辑器内核原生化（方案 A1）— 已执行

- 状态：**A1 已执行**，四类 bug 已全部修复（2026-09-11）。
  - A1（原生内核）：`src/editor/dom.ts` + `src/editor/kernel.ts`，`Editor.tsx` 退化为 95 行薄壳。调解层失效那一类结构性消失。
  - 光标算术与偏移映射两类：A1 不解决（实测确认），已在现架构上独立修复并补了失败测试（见 §7）。
- 关联问题：换行/光标类 bug 四类（标题与段落回车后光标错位、段落二次回车、列表退出后结构损坏、Backspace 后静默损坏）
- 项目定位：自研 Markdown 编辑器（Typora 语义）＋ 模型工程能力评测场。自研本身是目的，因此不采用第三方编辑器内核。

> 本文件于 2026-09-11 做过一次实测核查。核查中被证伪的表述已删除（不是加批注保留），替换为可复现的实测事实；证据与复现步骤见 §5。

## 1. 冲突的本质

浏览器与 React 争夺同一片 DOM 的写权限：

```
浏览器（用户输入时是 DOM 的唯一主人）
    vs
React（重渲染时也写 DOM，再把光标"重放"回原处）
```

**旧管线**（A1 之前）：keydown 里改模型 → React 重渲染 → layout effect 用 `pending` 把光标重放回 DOM。两次权威交替之间任何时序错位都会造成 DOM 光标与模型光标漂移，而结构性编辑（Backspace 删行、跨块删除）会让浏览器直接改掉 React"以为还在"的节点。这条链是 A1 的直接动机，现已由内核取代（改模型 → 重写 DOM → 同一同步帧放回光标）。

这条链**真实存在且会造成损坏**（见 §2 的 (c)），但它**不能解释全部换行类 bug**：实测表明四类里三类与它无关，属于框架无关的算术与映射问题。

## 2. 实测事实（2026-09-11）

### 2.1 四类 bug 分属两个层

| 现象 | 层级 | 位置 | 机制（实测） |
| --- | --- | --- | --- |
| 段落/标题行末回车后光标错位 | 光标算术 | 旧 `Editor.tsx:455-458`，现 `kernel.ts` 行末分支 | 行末分支未区分"当前行是空行"：`at = lineEndRaw + 1` + `caret = at + 1`，公式在空行场景给出 9（应为 8），DOM 与模型一致 → 纯语义错误。后续按键落在下一段开头（实测打字得到 `X第二段`）。**已修**：光标改为 `live + 1`（新行的行首），插入点仍在行尾换行符之后 |
| 段落二次回车"失效" | 同上 | 同上 | 同一个落点的下游表现；连续回车时文档按次增长，但光标始终停在下一段行首（6 次回车实测）。**已修**：同一处改动，光标逐行跟随新空行 |
| 列表退出后结构损坏 | 偏移→DOM 锚点映射 | `dom.ts` 的 `anchorForSource` 行边界判断 | 列表续行分支的 `caretNext` 算术**正确**（插桩实测 `intent=8`），放置层把它放到 **9**（实测 `intent=8 placed=9`）；于是第二次回车认为自己在"有内容的 bullet"上，把 `- 第二项` 写成 `- - 第二项`（静默结构损坏）。根因是行边界判断：`local >= lineEnd` 把行尾光标推给下一行。**已修**：改为"光标属于起始偏移不大于它的最后一行"，边界归属由源码布局决定（详见 §7） |
| Backspace 后静默损坏 | **调解层失效** + 拦截缺口 | 旧实现：Backspace 拦截只覆盖"块起点" | 标题行末回车 → 退格：一次退格吃掉标题末字并删掉一个空行，DOM 与模型永久分叉，光标脱离所有块，此后键盘输入被吞。全程无异常、无 `console.error`。**已修**：A1 消除分叉与吞键；拦截改为"光标位于任意源码行行首就只删那个换行符"，浏览器不再有机会自己删字 |

### 2.2 核查中被删除的错误论据

原文用以论证"重构很便宜"的三条，经核查两条不成立：

- ~~`lib/` 本就不依赖 React~~ → 精确事实：`editCommands.ts`/`view.ts`/`inline.ts`/`welcome.ts`/`files.ts`/`markdown.ts` 六个文件与 React 无关（前四个零 import）；只有 `theme.ts` 是 React hook，属外壳层，不在内核迁移范围内。
- ~~DOM 契约不变，现有 21 个测试继续有效，可作重构安全网~~ → 21 个测试全绿，但**不是安全网**：`assertDomMatchesSource` 的两侧用的是编辑器自己的 `readDocumentSource`/`normalizeTables`（自指，编辑器内部那条分叉检测用的同一对函数）；Enter/Backspace 之后**没有任何光标断言**；`clickInRun(…, 0.5)` 实测落在行尾，所以"测试点击标题中间再回车"实际测的是行末回车（而中线拆行实测是本仓库里少数完全正确的行为）；测试 2、3 还用精确字符串钉住了行末回车的当前输出。→ A1 期间**重写测试是必要工作项**，不是可选项。
- ~~IME 风险可控，已有原生 `beforeinput` 经验~~ → 精确事实：只有 `compositionstart`/`compositionend`；`beforeinput` 仅用作"置位开关"，**从不读 `inputType`**；合成期间不产生撤销快照。IME 面比原文描述薄，风险相应更高，但涉及的行为面也更小。

### 2.3 对成本估计有利的实测事实

- **调解层规模**：`Editor.tsx` 1083 行中约 **590 行（≈55%）** 只为弥合"React 以为的 DOM"与"浏览器改过的 DOM"而存在（含 `placeCaret`/`readCaret`/`readDocumentSource`/`stripForeignText`/`sanitizeDom`/`resetKey` 重挂载机制等）。A1 删掉的是这一半。
- **撤销不是新增工作**：`undoStack`/`redoStack` 已是纯模型快照栈（`UNDO_LIMIT = 300`），不使用浏览器原生撤销，随内核迁移即可。
- **功能面薄，要保的行为少**：粘贴无代码（依赖原生行为 + `sanitizeDom` 事后拆包装）；裁剪/复制、拖放、查找、移动端均无实现；`spellCheck={false}`。

### 2.4 无法证伪的触发条件

仓库内**没有任何计时、基准或 CI**；大文档延迟只有定性承认（README 已知限制）。因此"渲染层拖慢编辑响应"这条触发条件目前无法判定——不是"未观察到"，是"没有测量手段"。

## 3. 方案与结论

**A1（本 ADR 采用的"原生化"定义）**：保留 `contenteditable`，只把 block DOM 的所有权从 React 拿走——命令式 DOM 构建/更新、原生事件绑定、在构建 DOM 的同一同步帧内重放光标；React 退化为外壳。

- 消灭：调解层失效这一类（§2.1 第四行有实测实例），并删掉约 590 行调解代码。
- **不消灭**：光标算术与偏移映射这一类（§2.1 前三行）。它们框架无关，且会被原样移植到新内核——除非在迁移前修掉。

**A2（自研光标/选区引擎，放弃 `contenteditable`）**：out of scope。那是数月工程，且要亲手接回 IME、拼写检查、无障碍树、系统级查找。

**方案 C（采用第三方内核，如 CodeMirror 6 装饰器 / ProseMirror / Lexical）**：不采纳。理由：自研本身是本项目的目的之一。

**结论（2026-09-11 修订）**：A1 **已执行**。实现落在 `src/editor/`（`dom.ts` 命令式 DOM 与映射、`kernel.ts` 状态与原生事件），`src/shell/components/Editor.tsx` 退化为薄壳：只渲染可编辑宿主 `<div>`，从不渲染它的子节点。

四类 bug 都要修。**路线不由重构决定**，执行后实测确认了这一点：调解层失效那一类（Backspace 静默损坏）随 A1 消失；光标算术与偏移映射两类原样存活（§7）。它们只能在现架构上独立修。测试加固与重写仍待做。

## 7. 执行结果（A1 落地后实测）

同一份探针（§5），重构前后各跑一次：

| 场景 | A1 之前 | A1 之后 |
| --- | --- | --- |
| S3 标题行末回车 → Backspace | DOM 与模型永久分叉（`domTextMatches=false`）、光标脱离所有块、后续按键全被吞 | **已修**：DOM 与模型一致、光标在块内、打字正常落字。仍会吃掉标题末字——那是浏览器原生退格删的字符，模型忠实吸收，属另一类问题 |
| S1 段落行末回车 ×2 | 光标跳到下一段行首；打字粘成 `X第二段` | **完全不变**（算术） |
| S2 列表回车 ×2 | `- 第二项` 被写成 `- - 第二项` | **完全不变**（偏移映射） |
| S5 连按 6 次回车 | 光标停在下一段行首，不跟随新空行 | **完全不变**（算术） |

随后独立修复了剩余两类（同 §2.1），探针第三次跑。共四处改动：

| 场景 | A1 之前 | 现在 |
| --- | --- | --- |
| S1 段落行末 Enter ×2 后打字 | `第一段文字\n\n\n\nX第二段\n`（粘进下一段） | `第一段文字\n\nX\n\n第二段\n`（X 独占一行），光标 6 → 7 每次都跟到新空行 |
| S2 列表 Enter ×2 | `- 第一项\n- \n\n- - 第二项\n`（下一项被写坏） | `- 第一项\n\n- 第二项\n`（干净退出，下一项完好）；回车后光标 8 = 新 bullet 行尾（原为 9） |
| S3 标题行末 Enter → Backspace | `# 标\n\n正文\n`（吃掉标题末字）；DOM 与模型永久分叉、光标脱离所有块、后续按键被吞 | `# 标题\n\n正文\n`（只并回一行）；DOM 与模型一致、光标在块内、打字正常 |
| S5 连按 6 次回车 | 光标停在下一段行首 | 光标逐行跟随新空行（2,3,4,5,6,7） |

四处改动：

1. **行末回车的光标目标**（算术，`kernel.ts`）：`at + 1` → `live + 1`，光标落在新行的行首而不是插入点之后一行。
2. **行归属规则**（映射，`dom.ts` 的 `anchorForSource`）：改为"光标属于**起始偏移不大于它的最后一行**"。原先的 `local >= lineEnd`（后改成 `> lineEnd`）都在边界上二选一，而边界的正确归属由源码布局决定：空块的行起始于 0/1/2，光标 1 属于第二行；列表的 `- ` 行起始于 6、光标 8 处没有任何行起始，属于 `- ` 的行尾。
3. **退格拦截**（`kernel.ts`）：覆盖"任意源码行行首"，只删那一个换行符；原先只覆盖块首，其它位置交给浏览器，于是它从最近的文本节点里删字。
4. **空行的可编辑落点**（`dom.ts`）：空行重新渲染 `<br data-br>`。没有它，浏览器会把锚在空行里的光标解析回上一个文本节点的末尾——真实浏览器里表现为"回车后打字粘回上一行"；同时 `domToLocal` 补上"行盒内直接文本节点"的偏移计算，否则空行里打第一个字后模型光标被打回行首，输入逐字逆序（`二行第`）。

第 4 条**测试套件抓不到**：userEvent 派发的是合成（untrusted）事件，不进入浏览器自己的插入点解析。它是在 `tsc` 与 26 个测试全绿之后，用真实输入（CDP）复核才暴露的。README 的测试章节已记录这个盲区。

结论：A1 的价值是**删掉一整类失效**（DOM/模型分叉、丢光标、吞按键、`NotFoundError` 家族）并让约 590 行调解代码失效，而不是修掉换行类 bug 的全部——这与 §2.1 的分层判断一致，剩余两类确实只能在现架构上独立修。四处修复本身都很小。

## 4. 触发条件（满足任一即重新评估）

## 5. 证据与复现（记录的是修复前的观测）

探针：`src/test/adr-0001-enter-caret.probe.tsx`——命名不匹配 `*.test.tsx`，因此 `pnpm test` 不收集它、`tsc -b` 仍会检查它；运行方式见文件头（复制成 `src/test/probe.test.tsx` 即可）。按键走真实键盘路径；光标用原生 `Range` 定位（`clickInRun` 的坐标映射会把"文字中间"的点击落到行尾）。

- **静默损坏（S3）**：文档 `# 标题\n\n正文\n` → 点击标题行末（偏移 4）→ Enter → Backspace。观测：模型 `# 标\n\n正文\n`，DOM 文本 `# 标\n正文\n`（分叉），光标 `null`（不在任何块内），随后打字被完全吞掉，`window.error`/`console.error` 均无输出。
- **列表结构损坏（S2）**：文档 `- 第一项\n- 第二项\n` → 光标在首项行末（偏移 5）→ Enter ×2。观测：`- 第一项\n- \n\n- - 第二项\n`；此时打字得到 `- X- 第二项`。
- **光标错位的用户可见后果（S1）**：文档 `第一段文字\n\n第二段\n` → 行末 Enter ×2 → 打字 `X`。观测：`第一段文字\n\n\n\nX第二段\n`——打出来的字粘在下一段开头。
- **插桩测量**：在 `commit` 打印 `caretNext`、在 `placeCaret()` 之后打印 `readCaret()`：列表 Enter#1 得 `intent=8 placed=9`（算术正确、映射多推一位）。

## 6. 执行记录

1. **迁移内核（已完成）**：`src/editor/dom.ts`（命令式 DOM 与双向映射）、`src/editor/kernel.ts`（状态、原生事件、同帧光标）；`Editor.tsx` 退化为薄壳；`lib/` 与撤销栈原样随迁。
2. **三类 bug 复现成失败测试（已完成）**：`Editor.test.tsx` 新增三条（段落二次回车后打字不粘进下一段、列表续行光标落在新 bullet 上且退出不损坏下一项、标题回车后退格不吃字）。三条先红后绿。
3. **测试分层（已完成）**：`vitest` 拆成 `unit`（node，纯函数）与 `browser`（真实 Chromium）两个 project。纯函数层逐语法覆盖了解析/视图映射/行状态/列表/编辑命令——视图的**无损往返**（`runs` 拼回源码）在纯函数层独立断言，正是浏览器层 `assertDomMatchesSource` 原本想守的不变量，且不再两侧同源。
   这一步顺带发现三处真问题：`parseDocument` 每块都在预渲染并 sanitize HTML（`Block.html` 无人消费，纯烧性能且把 parser 钉在 DOM 上，已删）；围栏标记不区分 ``` 与 ~~~（两处实现都错，已修）；在图片 alt 里插链接会产出无法解析的嵌套（已加守卫）。
4. **浏览器层测试缺陷（已完成）**：`clickInRun(…, 0.5)` 实际落行尾（"中线"用例测不到中线）。根因有三层，都在助手里：(a) `userEvent.pointer` 的 `coords` 是**视口绝对坐标**，旧代码按"相对目标元素"传 `rect.width * 0.5`，于是每次点击都落在页面左上角、行盒之外，编辑器的落点回退正确地回答"行尾"；(b) 合成事件没有浏览器默认动作，选区根本不会跟着点击走；(c) 即便坐标对了，行盒边缘的浏览器解算本身就差一个字符（`rect.right` 时而解到最后一个字符、时而解到末尾）。
    修法：参数从"宽度比例"改成**字符位置**（`'start' | 'middle' | 'end' | 下标`），点击仍按真实坐标派发（编辑器的命中测试照跑），随后由助手把选区放到那个字符上——即浏览器默认动作本该做的事。回归证明：把助手改回旧行为，"点击标题文本中间后按 Enter"与"表格单元格可点进去就地编辑"两条立刻变红。顺带把那条用例的断言改成"两半拼回去仍是原标题"——它以前只是"行数变多了"。
    仍未做：Enter/Backspace 之后的光标断言还不够密。
5. **验收**：`tsc -b` 干净；21 + 3 条回归全绿（23/23）；探针 S1–S6 浏览器实测。
