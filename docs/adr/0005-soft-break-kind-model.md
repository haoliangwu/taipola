# ADR-0005: 软换行的 kind 模型——会话态是渲染唯一多出来的变量

- 状态：**已定案，未执行**（2026-10-11 议会评审定稿，用户拍板）。落地分两刀：
  第一刀 = 测试基建 + kind 数据层；第二刀 = kind 驱动渲染。
  统一验收物：`.scratch/soft-break-cuts/test-matrix.md`。
- 关联：ADR-0001（谁是 DOM 的主人）、ADR-0002（光标不变量——本 ADR 的 §3 替换其中
  「空分隔块不再渲染行盒」与「占位块/尾随块」两条的**判定输入**：从手势状态换成 kind）、
  ADR-0004（写回——规范化边界在 §2.4 写死）、`.scratch/council-review/2026-10-11-report.md`
  （诊断与遗漏清单）、`.scratch/soft-break-stack/`（回归墓碑）。
- 为什么单独占一份 ADR：未来读者打开一份昨天还带软断链的文档，按 F5，看见所有空行
  塌成段距，会问「谁杀了我的行盒」；或者打开这份 ADR 之前想给 kernel 再加一个
  `measured:` 分支——这个「为什么不再加了」不写在代码里，只能写在这里。

## 1. 背景

### 1.1 回归史

软换行/空行渲染是这个编辑器最大的回归源，三次线上故障都在同一片：

1. **线上首报（e6bbdc1 部署版）**：`aaab` 行中 Shift+Enter ×5 → 一屏空白行；一次
   Backspace 整链消失，之后要按很多次才能回原状（`.scratch/soft-break-stack/`）。
2. **回归 1/2**：末次弹栈后光标停在不可见的段落分隔空行上，下一次 Backspace 吃正文；
   中行起始的链弹完一格后整链行盒消失，后续弹皆不可见。
3. **回归 3/4**：弹链时光标逐次「上移一行」漂移；光标离开后整链行盒塌缩——用户原话：
   「编辑状态是有换行的，变成预览状态中间的空行反而消失了」。

每一次修复都在 kernel 里加题型机制：`pendingBreak`（enter / soft / prefix 三种 kind）、
`softChains`（会话记忆）、占位渲染三态（`data-ph-sep` / `data-ph-sep-after` / 全显）、
re-home 容差三兄弟（nearEnter / nearSoft / diff 插行判定）。到 `5519eeb` 时，commit 里
165 行的 diff 启发式与十几条 `measured:` 注释互相支撑，也互相绊脚。

### 1.2 诊断

> 病根 = **「DOM 读回 + diff 反推意图」**：内核假设浏览器改出来的 DOM 能反推出用户的
> 手势本体。软换行是二等公民的直接后果——`甲\n\n\n乙` 的字节无法表述「这些空行是谁的」，
> 于是身份判定每次都退化成推 markdown-it、看手势时机、看占位标记。

这条路线的输出就是回归本身。正确的问题不是「怎么修第 17 次」，而是
**把「身份」从字节之外的一等状态里接住**：会话里产生的空行与文件里的空行，
本来就不是同一种东西，只有会话态知道区别。

## 2. 决定

### 2.1 kind：分隔行 identities 的会话态数组

- **只键在空行上**。内容行永远渲染（不进 kind 空间）；段内软断行（`甲\n乙` 的 `\n`，
  两行都有内容）也永远渲染、删除和普通字符完全一样——它不需要 kind。
- **两值**：
  - `soft`——段内换行身份的本会话产物：**本会话产生的恒渲染行盒、光标离开不塌；
    Backspace = 删光标正前那个 `\n` 的普通字符删除**（回归 3 的 Typora 裁定）。
  - `structural`——段落分隔：渲染为段间距、不出行盒（间距由 `data-gap` 承接）。
    一次会话里任意多个相邻 structural 分隔行合作出**一个**段间距——
    文档观感不变（web 实证：Typora `\n\n\n` 也只显示一个段间距）。
- **初始化**：载入、刷新、外部改动恢复——**全部分隔行一律 structural**。
- **会话期**：Shift+Enter 开出的每一根空行记 `soft`；**Enter 家族开出的新段占位行
  同为会话空行，也记 `soft`**（行尾 Enter 的空块增长、行首 Enter 的上插空行、
  空行上的 Enter 增长）。空行被内容消费后（打字围段 / 链上编辑改写）条目清除，
  回到 structural——既有锁定用例（「两侧各一个空行」「打字不粘进下一段」）逐字不变，
  判定输入从 pendingBreak 标记换成 kind 条目。
- **不持久化**：不进 localStorage、不进草稿编码、不进写盘文件。会话内唯一状态。
- **重开即收敛**：kind 数组重开/刷新/外部改动后清空，一切空行按文件面目的 structural
  渲染。这是会话态的明确上限（§4）。

### 2.2 渲染 = kind 驱动的纯函数管道

`(src, kind) → expandedDoc → DOM` 两段接缝。expandedDoc 只读 (src, kind)：

- 内容行恒渲染（与今天一致，含 ADR-0002 里所有行盒规则）；
- `soft` 分隔行渲染自己的行盒（`<br data-br>` 落点，`--doc-line-size` 高）；
- `structural` 分隔行不渲染任何节点；
- 管道不再读待办标记、不读 softChains、不读手势状态。**第二刀落地时，
  `pendingBreak` / `softChains` / 占位渲染三态 / re-home 三分支全部删除**；
  新的输入只有 (src, kind) 与光标。对空行打字的段落化（paragraphize）保留——
  它是 `(src, kind, caret)` 的状态规则（光标在 kind 条目指出的一根空行+插入字符 →
  围段），不是 diff 推断的 re-home 分支；`assertDomMatchesSource` 语义原样有效。

**判定输入变化对位**：「这个空行该不该画行盒」过去由 pendingBreak 的 soft/prefix 三态
+ softChains 记忆 + 占位选择器回答；现在只由 kind 数组回答。Nowhere else.

### 2.3 管辖边界

kind 只管 **段落软链**（家族 ①）。契约性排除：

- **②** 引用/列表行的 Shift+Enter（前缀复制 / lazy continuation）——新行带重复的
  前缀（`> `-、`- `-），是内容行，渲染本来就有着落，不进 kind；提交/验收不回归。
- **③** 表格单元格换行（Shift+Enter → `<br />` 字面源码、Enter → 同列下一行）——
  单元格是 grid，不进 kind；同上维持现状。

这三家与软链共享的只有「都往 kernel 里打 Enter」这一件事。kind 数据层若误把
②③也键进去，第一刀就算失败。

### 2.4 规范化边界（二选一问题，裁定为对称字节守恒）

写回（ADR-0004 的写盘通道）的 toMark 类规范化，与「未编辑区域字节不变」存在冲突。
裁定：**规范化边界 = (a)，保存/写回的规范化仅限用户编辑过的行**；未编辑区域
**字节逐字不变**。

- 用户编辑过的行：允许按惯常格式清洗（trailing whitespace、表格列对齐、块尾空行剥写
  等），这也是 markdown 惯常做法。
- 未编辑过的行：一个字节都不许变。用户只想在文档末尾敲一个字，前 1000 行即使在
  别的编辑器里排成了另一种形态，本编辑器的写回也不能动它。
- 不做全文档 hash 比对——那是另一种幽灵 diff。边界以**本会话的编辑记录**（被
  commit 实际改写过的行）为准。

理由：写回式编辑器持续动用户磁盘上的文件；没有字节不变边界，任何会用别的工具
（git merge、别的编辑器、CI 格式化）的用户都会被「幽灵 diff」毁掉一次。
(council 清单 #9：toMark 与字节不变冲突，必须二选一，推荐就是 (a)。)

## 3. 不变量

与 ADR-0002 的不变量同级。违反任何一条，症状回到 §1.1 的某一幕。

1. **渲染 = (src, kind) → expandedDoc → DOM 的纯函数管道**。renderDocument 不读
   pendingBreak / softChains / 手势状态。任何「这个空行画不画」的问题必须
   (src, kind, caret) 三元可答；答不了的画法，进 §4 天花板而不是加比特。
2. **每个源偏移恰好一个 DOM 落点**。任意偏移 o：
   - 落在渲染行（内容行、soft 空行盒）→ 行盒内偏移映射（`<br data-br>` 行的规则
     维持 ADR-0002 的单落点约束）；
   - 落在不渲染的区间（structural 分隔行、空间隔块）→ **回走**到最近的前一个
     渲染块的末尾。规则唯一，全域 flat mapping，**不允许每一处一个例外表**。
   全偏移 property test（矩阵 §E-1）锁死。
3. **kind 驱动可见性**。行盒显隐只由 kind 决定：soft = 恒显（光标离开不塌）；
   structural = 恒隐（光标在场也不显）。禁止再走「光标在场才显」——那是回归 4 的根因。
4. **Backspace-in-soft-chain = 删光标正前那个 `\n`**。光标任意的 soft 行上，退格
   删除 `doc[caret−1]`，**光标落在被删偏移**（骑行盒回走，位置相对不变，不跳到上一行），
   行盒减一；永不删除正文（矩阵逐格断言，GIF 即回归 3 的 cy。链弹尽后下一次
   Backspace 走 structural 并段的同一条纯函数路径，同样零手势分支。
5. **undo/redo 快照含 kind，整体 restore 而非 delta 平移**。snapshot =
   `{value, caret, kind}` 三元组；undo/redo 一次性整体恢复三份，不走 followSoftChains
   这类偏移推理。合成期间（IME composing）禁 undo——现状 mod+Z 在 composing 检查
   之前执行（kernel.ts 的 mod-Z 分支，council 清单 #2），会把未提交拼音读进模型，
   第一刀修掉。
6. **文档无损且 assertSourcePreserved 一直安静**。kind 数组的键随 commit 平移，
   随行亡剪除，永不携带指向不存在或非空行的键。

## 4. 天花板（写死，不许往上碰）

1. **重开即收敛**。kind 是会话态：重开文件、刷新页面、外部改动恢复后，一切分隔行
   structural，本会话产生的行盒全部消失。不接受「重开后仍然保留会话视觉」。
2. **文件原有空行与本会话软断行，字节不可区分**。字节一样，语义不同——
   kind 只能对**本会话**创建/改写过的空行给出身份。它回答不了
   「上一个会话」与「文件原状」的多标签 last-write-wins、undo 跨文档断头
   （council 清单），通通只在第 2 条天花板之内。

任何未来的 feature request 撞第 2 条天花板（如「刷新后软断链还活着」），
答案永远是「不」；唯一妥协是持久化 kind，而这已经在 §2.1 明确否决——
否则文件里就要出现编辑器私有标记，与 §2.4 字节不变冲突。Typora 版本的上限
也在此：Typora 是会话内幂等的编辑器，我们的 kind 不是（目的就是给字节
不能承载的信息一个安放之地），代价必然是「重开即塌」。

## 5. 代价与 Trade-offs（对 Typora 的等价以保存时刻为界）

- **会话内等价**。用户会话内的观感（软链恒显、弹链光标回走、Backspace 逐格退、
  行尾 Enter 的空行可见且不塌）与 Typora 同。
- **保存之后到重开之前，等价腰斩**。本会话产生的空行与文件空行字节同形；
  别的工具（VSCode、Obsidian、GitHub preview）把所有空行当段落分隔——
  重开即收敛。用户从本编辑器转出，看到的永远是一份普通 Markdown 文件。
- **kind 数组的实现成本**。第一刀只要数据层 + 快照含 kind；第二刀要做渲染重写 +
  三个分支家族的删除 + `data-ph-sep` 类占位 CSS 的退役。这是本 ADR 两刀分开的
  直接原因：渲染重写不能和数据层、测试基建混做。
- **「退出层」的用例迁移**。`softBreakStack.test.tsx` 的「离开堆栈行盒消失」是
  过渡断言（Regression-4 明示会被替换）；目标断言改用
  `persistedChain.test.tsx` 的「离开仍渲染」。矩阵 §G 的清单给出日落名单；
  其余 567 例为不回归基线。
- **对 Typora 等价的明激烈偏离**：`/1` 处第一刀不改变任何可见行为，
  第二刀是**产品级视觉变更**（sessionEnter 家族不再「光标离开即塌」——见 §2.1）。
  预期管理：用户 Feedback 走 matrix 的视觉验收，不臆测。
