# ADR-0002: 光标与源码映射的不变量，以及踩过的坑

- 状态：**参考性记录**，不是一次决策（2026-09-12 从 README 迁入）。
- 为什么单独占一份 ADR：README 已经精简成一份对外介绍，原本那两节（「关键约定与不变量」「会破坏光标的坑」）
  在别处没有任何副本。它们是后续所有改动的输入——改块收集、改 run 分段、加一种行内语法之前，先读这份。
- 关联：ADR-0001 定了「谁是 DOM 的主人」。这份记的是那条路线定下来之后，必须**一直**成立的东西，
  以及破坏它们时屏幕上的具体症状。

## 1. 不变量

这些不是风格建议。违反任意一条，症状都是「光标跑到别处」或者「屏幕和源码说的不是一回事」。

**偏移的约定。** `ViewRun.src` 与 `data-src` 一律是**块内**偏移，`.blk` 的 `data-src-start` 是文档偏移，
换算只在点击处理器里做一次。表格单元格的 run 已经带块内偏移，不能再叠加 `pieceStart + lead`——
叠加之后从第二个单元格起映射全错。

**一个源码行 = 一个行盒。** 光标的定位算术按源码行建索引、按行累加基线。段落内的软换行把两端都改成
`inline`（`vl-soft` / `vl-continues`），让它们合成一行、由列宽决定折行，但行盒本身仍按源码行切分。
那个换行由 `::after { content: ' ' }` 补回；伪元素不进 DOM，所以从 DOM 重建源码时换行还在。

这条不变量有两半，**都要成立**：

1. **每个行种都有一格高度**，哪怕它此刻没有可见文字（`---`、围栏行、空的列表项）。高度由
   `--doc-line-size`（`calc(var(--doc-line) * 1em)`）这个**长度形式**给，`line-height` 用的仍是
   无单位数 `--doc-line` —— 两者必须从同一处派生。写成 `min-height: var(--doc-line)` 是空操作
   （无单位数不是长度），后果是"光标一进代码块整块长高 26px"（`.scratch/table-ops/issues/02`）。
   表格的 `| --- |` 行与代码块的围栏行是**刻意**的例外，各自的 CSS 里写了理由。
2. **一个行盒的高度不能随光标进出块而变。** 保住它的做法是让显现态与折叠态的盒子一样高：
   围栏行的高度来自它自己的行盒，而不是 padding —— 一旦给围栏行加 `padding-block`，光标进块时
   围栏标记显现成文字，行盒会多出一个文字行，整块跳一下。

**表格行是一格一格的盒子。** `buildTableLine` 把一行切成 CELL（`cellRuns` / `cellSrcs`），DOM 里
每个 CELL 是一个 grid item，带 `data-cell-src` = 这一格**内容起点**的块内偏移。空格子渲染不出 run，
所以它的落点只能来自 `data-cell-src`：回落到"整行行首"就会落到**第一根管道之前**，在那里打的第一个字
会让这一行不再像一行表格（`.scratch/table-ops/issues/01`）。分隔行是唯一没有格子的行，它的源码靠一个
hidden run 保留 —— 那个 run 必须**跟着源码更新**，写成一次就不管了的话，任何对分隔行的修改都会被读回成
修改前的文本（`.scratch/table-ops/issues/03`）。

**run 分段在隐藏与显现两个状态间保持一致。** token 边界和块级标记边界在扫描时就定死，显现只切换 CSS 类、
从不替换文本节点。否则锚在相邻文本里的光标会被挪走。

**源码是权威，DOM 只是反射。** 光标状态是源码偏移。内核放好光标后置位 `placedByUs`，只有用户手势会清它——
不然浏览器夹紧之后的读回值会污染模型，光标会按每个显现标记的长度往回走。

**块视图按行跨度补足空行。** 解析器会把块尾的空白行从 `raw` 里剥掉（markdown-it 的列表范围常覆盖末项之后的
空行），视图必须按 `endLine - startLine` 补齐空行盒，否则空行上的光标没有落点。注意剥掉的只能是**换行**：
只有空格的行对 Markdown 是空行，但那几个字符是用户的源码，必须留在块的 `raw` 里（§2 第 8 条）。

**空白行必须带一个 `<br data-br>` 落点。** 行盒里没有文本节点时，浏览器会把锚在其中的光标解析回上一个
文本节点的末尾，用户看到的是「在空行打字，字跑到上一行」。这个 `<br>` 不参与源码重建，`textOfLine` 只读 run 和
单元格文本。判据是「**这一行是空白行**（`isBlankLine`：空的，或只有空格与制表符）」，而不是「这一行没有可见格」：
折叠的围栏行、分隔线、空的列表项同样没有可见格，但它们是内容、行盒本来就有高度，塞一个 `<br>` 进去等于凭空多出
一条线（实测 `---` 那行 1px → 27.25px）。表格分隔行是另一种形状，它走自己那条路（见 `render.ts`）。

**空白行的字符活在折叠 run 里，整行只有一个光标位（行首）。** 只有空格/制表符的行，视图把它们作为**一个折叠
run**（`marker: true`）交出来——源码因此能逐字从 DOM 重建，而这一行看上去仍是空行。代价必须写明：折叠 run 没有
排布出来的格子，光标放不进去，所以这样的行只有一个落点（行首），在上面打字的字符落在那几个空格**之前**
（`   ` → `X   `）；想精确编辑这些空格，只能先把这一行变成有可见内容的行。`anchorForSource` 对此返回
`runIndex: -1`（"这一行没有可落位的 run"），`applyCaret` 于是锚在行盒上；`domToLocal` 读回时若该行没有任何
排布出来的 run，也取行首——读成"最后一个 run 的末尾"会让下一次 Backspace 吃掉空格而不是换行
（`.scratch/whitespace-round-trip/issues/01`）。

**已知口径差异：** `isBlankLine` 只认空格与制表符，而解析器/`inline.ts` 用的是 `raw.trim() === ''`（还包含 `\f`、
`\v`、NBSP 等）。夹在中间的行（例如整行只有一个 NBSP）对 Markdown 是空行，对本视图却是**有内容的行**：它照常
渲染成可见 run、光标也照常有多个落点。这是刻意的——屏幕上有字形的东西就该能编辑。另外，缩进代码块（4 空格）
不在 `inCode` 里（视图只认围栏），所以缩进代码块里的空白行按空白行处理。

**空行本身是一个落点，光标不跨空白行回退。** 删掉光标前的换行之后，落点就是那个换行原来的位置：光标本来在
**空行**上，删完仍在剩下的那段空白上，连按 Backspace 就是逐个减少空行。只有当光标所在**行内有文字**（把下一行
并上来）时，才继续往回走到上方内容的末尾——那是 `backspace-join/01` 要的落点。把两者混起来的症状见 §2 第 7 条。

**Enter 永远被接管**，光标在块外时也不例外：块外的回车在文档末尾追加换行，块内的回车按列表、引用、普通行各自的
语义改写源码。原生 contenteditable 的 Enter 会往 DOM 里注入 `<br>` / `<div>`，那属于事后还得吸收的垃圾；
`input` 路径里仍会清掉已经混入的孤儿元素，并把它里面的文本救回来。

**每次 input 从 DOM 重建整个文档**，不是只重建光标所在的块。跨块编辑（全选删除、拖选删除、粘贴）由浏览器同时
改动多个块，只吸收一个块会丢内容。`userEditPending` 由 `beforeinput` 置位、`input` 消费。

**`assertSourcePreserved`（dev）要一直安静。** 每个块都必须恰好覆盖源码对应的区间，一字不丢。改块收集逻辑时留意它。

## 2. 会破坏光标的坑

按踩到的先后排列，每一条都真的发生过。

| # | 症状 | 原因与规则 |
| --- | --- | --- |
| 1 | 输入逆序：打 `ABC` 得到 `CBA` | `focus()` 会重置选区，所以必须先 `focus()` 再 `setRange()`。反过来写会静默丢掉刚设好的光标，之后每次击键都插到行首。另外要 focus 的是可编辑根 `.doc`，不是内部的块 `div`——块不可聚焦，键盘输入会落空 |
| 2 | 模型更新之后选区跳回偏移 0 | React 重渲染会重置 contenteditable 里的选区。旧实现只能把光标位置存进 `pending`、在 layout effect 里重新应用；这是内核化（ADR-0001）最主要的动机之一。现在 DOM 由内核写、光标在同一帧内放回，这一层不存在了 |
| 3 | 点击之后光标停在原处 | 块已经是可编辑态时，只 `preventDefault()` 而不自己算位置，浏览器不会动光标。得用 hit-test 找到 run，再按 `data-src` 加测量换算出源码偏移 |
| 4 | 列表、标题、引用永远没有编辑态 | 早期实现只在光标位于标记本身时才显示前缀。规则必须是**块级**的：光标在块内，该块所有行的前缀都显现；离开即折叠。配合上面「分段一致」，显现过程不会移动光标 |
| 5 | 多行块里除第一行以外，行内标记永不显现 | `revealFrom` 必须是**行内**偏移。曾经把块内偏移直接拿去和行内 token 偏移比较 |
| 6 | 画出来的标记和源码同时出现，读作 `[1][^1]: 小小补充` | CSS 画的标记要门在 `:not(.revealed)` 上（脚注定义的 `[1]`）。由 mark 驱动 CSS 的那些（脚注引用的方括号）得在**视图**里撤销 mark，因为 mark 才是「CSS 画不画」的决定者。同一处还有一条：上标的 `line-height: 0` 是承重的，不写它行盒会被撑高，而光标算术按「一个源码行一个行盒」建索引（实测定义行 26.25px，与相邻行一致） |
| 7 | 空行上按 Backspace：光标被甩到上一段末尾，**再按一次删掉的是正文**；空行越多越明显（4 个空行时第 2 次就吃字） | 合并分支无条件 `while (joined[caret - 1] === '\n') caret--`，把落点从"删掉的那个换行"一路退到上一个非空段落的末尾——而那里正是那段文字的最后一个字符。规则见 §1「空行本身是一个落点」；票据 `.scratch/enter-backspace-smoke/issues/09` |
| 8 | 只有空格的行在下一次按键时**静默消失**，同一份文档里输入还会落到文档末尾 | `pushBlank` 把 blank 块的 `raw` 写死成 `''`：字符在**解析阶段**就没进模型，视图自然无物可画，DOM 里一点痕迹都没有，而 `input` 每次都从 DOM 重建整篇源码——于是缺失被写回。模型少了 3 个字符，光标偏移随之错位（输入落到文档末尾）。修法是让模型完备（`raw` 保留非换行字符）+ 视图用折叠 run 交出来（§1 最后两条）；票据 `.scratch/whitespace-round-trip/issues/01` |

## 3. 这些约束由什么钉住

把不变量写进文档，不如让它变红。目前：

- `src/editor/position.test.ts` 直接断言偏移映射的规则：行归属、折叠标记吸附、空行落点、offset 与 DOM 位置的往返。
- `assertDomMatchesSource`（`src/test/editorTestUtils.tsx`）断言 DOM 每行拼接之后与源码逐字一致。
- `src/core/view.test.ts` 的往返断言要求 runs 能一字不差拼回源码。
- `src/core/markdown.test.ts` 断言空白行的字符留在块的 `raw` 里（§2 第 8 条的反面：模型先丢字，后面全塌）。
- `src/shell/components/Editor.test.tsx` 覆盖光标落点、按键拦截、跨块删除、软换行，以及脚注的编辑态。

动这些地方之前，先读 §1。
