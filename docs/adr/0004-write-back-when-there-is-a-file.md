# ADR-0004: 有文件就写回——内容的保证从本机草稿挪到磁盘

- 状态：**已执行**（2026-09-14）。落地票据 `.scratch/folder-sidebar/issues/01-auto-write-back-with-a-file.md`，
  提交与验收证据写在那张票的 `## Comments` 里。
- 关联：`.scratch/folder-sidebar/spec.md`（取舍全文）、`CONTEXT.md`（写回 / 草稿的定义）、
  `.scratch/unsaved-guard/issues/01-lossy-operations-do-not-all-confirm.md`（本决定推翻它的前提）、
  `.scratch/draft-tabs/issues/01-tabs-share-one-draft-slot.md`（本决定取代它的「草稿全局一份」）、
  ADR-0003（同样是一条先定语义、UI 后补的决定）。
- 为什么单独占一份 ADR：未来读者打开一个文件、敲两个字，发现磁盘上的文件被改了，会问
  「谁允许它这么做的」。这个「为什么」不写在代码里，只能写在这里。

## 1. 问题

编辑器里「内容的保证」一直是**本机草稿**（localStorage），磁盘只在用户显式保存时才更新。
草稿是尽力而为的存储——清理站点数据、隐私模式、配额满都会带走它——所以任何会替换当前内容的
动作都必须先弹一次确认：打开文件问、新建问、离开页面拦。

这条链的源头不是弹窗太多，而是**保证放错了地方**。Typora 的语义是「内容时刻与文件同步」，
所以它切换文档时不需要问任何问题。

## 2. 决定

**只要当前文档有对应文件，改动就自动写回那个文件。**

- 有句柄：改动停止约 1 秒后写回；写回前比一次文件的修改时间，与打开时记录的不一致就问一次
  （唯一保留的确认）。
- 没有句柄（欢迎文档、未命名、刷新后尚未重新打开的文档）：行为不变——仍旧只有显式保存，
  仍旧有未保存提示与离开页面的拦截。
- 写回失败（权限被撤、磁盘满、文件已被删）：提示一次，停掉自动写回，内容留在草稿里。
- 草稿的角色从「保证」降为「崩溃网」：按文档分槽、只记尚未写回的内容、写回成功后删除。
- 由此，切换文档、新建、打开文件**不再询问**。

## 3. 代价

- **这个编辑器会自己改用户磁盘上的文件。** 打开一份文件、误敲一个字符，磁盘就变了。这是 Typora
  语义的直接后果，接受它，但要求：没有文件的文档绝不假装已落盘。
- **引入一次新的确认场景**：磁盘上的文件被别的程序（`git checkout`、另一个编辑器）改过时问一次。
  它不违背「切换不询问」，但它确实是一次新的打断。
- **写盘比写内存贵**：1000ms 的防抖是为了让连续输入不至于变成连续写盘。
- **草稿的身份不稳**：文件系统访问 API 只给到目录名，两个同名文件夹会有相同的槽键。在句柄
  持久化（与 Electron 移植合并）落地之前，这是一个被明确接受的残留风险。
- **「未保存」变成瞬态**：从前它表示「只在内存里」，现在它表示「还没写回」。启动时从草稿恢复的
  文档因此被判为未保存（今天为假）——这是有意的行为变更。

## 4. 留下的东西

- `CONTEXT.md` 里「写回」与「草稿」的定义：写回是内容的去向，草稿是尚未写回的那一份。
- 一条给未来的约束：写回必须走**既有的**保存通道（权限语义、失败返回、单例接缝都不变），
  自动化的只是触发时机，不是写入方式。
- 一条给未来的口子：目录访问与文件身份全部关在适配器接缝后面，Electron 用真实路径之后，
  上面那条「同名文件夹」的残留风险随之消失——届时可以重开这份 ADR 的第 3 节。
